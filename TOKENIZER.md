# Bootstrap tokenizer

Use `paracine tokens file.pcn` to print the normalized-source line and byte column, kind, and (for identifiers, keywords, numbers, and symbols) spelling of each token. String and character payloads are not printed by this command. Lexical errors carry a stable `E` diagnostic code and a 1-based `line:byte-column` location in normalized source; malformed UTF-8 is reported at its invalid byte (or the start of an incomplete sequence), not as a bare byte offset.

The tokenizer validates UTF-8, normalizes line endings and NFC, removes a leading UTF-8 BOM, and adds a final newline when needed. Identifiers use Unicode 15.1.0 `XID_Start` for the first scalar and `XID_Continue` thereafter, with underscore additionally permitted as a start character. This admits Unicode letters and the standard combining marks, digits, and connector characters in continuation positions. Reserved keywords remain the existing ASCII spellings. Numeric, text and character literals, comments, punctuation, and indentation tokens are also recognized. The compiler accepts some compatibility keywords beyond the edition-2026 reserved vocabulary.

Decimal, hexadecimal (`0x`) and binary (`0b`) numeric literals support underscores between digits. Decimal literals also support fractional and exponent parts. A decimal point starts a fractional part only when followed by a digit, so `1..=4` is tokenized as a number, range operator, and number. Unsupported adjacent alphabetic numeric suffixes, invalid radix digits, malformed separators, and incomplete exponents are rejected with lexical diagnostics. Punctuation uses longest-match recognition.

Structural indentation is counted in ASCII spaces only: each level is exactly four spaces, and any tab before the first significant token of an ungrouped, non-continuation line is rejected at the tab's byte column. Blank and comment-only lines do not affect indentation and may contain tabs. Tabs are also accepted as ordinary horizontal whitespace between tokens, inside delimiters, and before a pipeline continuation; they do not contribute layout there. Other Unicode whitespace is not treated as a separator. Locations refer to normalized UTF-8 source and use byte columns, not offsets in the original file. Each token also carries an end-exclusive source span and normalized-source byte offsets. `IncrementalLexer` accepts byte-range replacements and returns the minimal changed token interval, replacement tokens, and the normalized-source offset where rescanning began. Edits are transactional, and malformed UTF-8 leaves the prior state unchanged. Edits restart at the nearest preceding top-level token boundary with balanced delimiters and indentation, retain the unaffected token prefix, and re-lex from that boundary to the end of the source; whole-buffer normalization still occurs before rescanning to preserve newline and NFC semantics.

Canonical edition-2026 reserved words and compatibility-only keywords are maintained in separate lexer tables. Compatibility spellings are explicitly documented above and must not be added to the canonical keyword list without an edition change.

This describes the current bootstrap implementation, not complete edition-2026 tokenizer conformance.
