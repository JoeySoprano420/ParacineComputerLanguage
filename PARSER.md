# Bootstrap parser

The bootstrap parser accepts a trailing comma after the final item in routine parameters, call arguments (including method, generic and pipeline-stage calls), closure parameters, variant payload parameters, array literals, and record constructor fields. Lists may span lines where grouping permits it. A trailing comma does not introduce an empty item; missing items and repeated commas are rejected.

Missing expressions and expected symbols report `E0202` with the normalized-source line, byte column and encountered token. Missing identifiers report `E0203`. Lexical delimiter errors can be reported before parsing.

## Recovering parse and syntax representation

Compilation uses `Parser::parseRecovering`, which returns a partial AST, all collected syntax diagnostics, and a token-backed `SyntaxTree`. A syntax error in a statement synchronizes at the next statement line; an error in a top-level declaration synchronizes at the next top-level declaration. This permits later independent errors (and later valid declarations) to be reported in the same pass. The compatibility `Parser::parse()` entry point still throws the first diagnostic for existing callers. Imported parsers recover independently and compilation collects their errors with file identities and import chains. A lexical error ends lexing for that file, while independent imported siblings can still be checked; malformed token streams are never fabricated.

The syntax tree retains normalized source verbatim and an ordered token stream containing each token's original source spelling, leading trivia, span, and byte offsets. Layout tokens are represented as zero-width tokens. Its hierarchical nodes group top-level items, indentation blocks, and balanced delimiter groups; token leaves retain their exact spelling and leading trivia, so concatenating token trivia and spellings reconstructs the normalized source exactly. Recovered parser diagnostics are attached as error nodes and mark their containing nodes. Node indices are stable only within one tree snapshot: cross-edit node identity, parser reuse, and comment-aware transformation APIs are not yet provided.

The compiler pipeline now exposes the pass order explicitly: lossless lex/syntax capture and recovering parse; canonical source-module graph discovery; public export-set closure and scoped symbol/type rewriting; public-routine normalization and constant resolution; declaration collection; declaration name/type resolution; body type checking; semantic analysis; specialization; and PCIR lowering. The graph supports cyclic declaration imports and explicit `public import` re-exports. `import module as M` binds qualified `M.name`/`M::name` references. Headers enforce private/public boundaries; headerless sources retain legacy implicit exports. Rewritten AST nodes retain source spans, and closures parsed in different files receive distinct deterministic compilation-local identities. Unchanged imported syntax can be reused in-process, but graph resolution and semantic checking run again. These named pass boundaries do not mean every local binding operation or per-module incremental semantic cache has been extracted from type checking.

Source package imports require an exact SHA-256 lock and resolve only the authenticated `vendor\name\version\package.pcn` source. Vendored sibling/submodule imports and manifests with transitive dependencies are rejected with `E0569`; they require a future authenticated file inventory. Optional identity-only vendor manifests must match the locked package identity. Unknown package manifest directives, including build scripts, are rejected rather than executed. See README for registry trust and offline policy.

A standalone `@allow(W0306)` before a routine (including a public routine) suppresses its unreachable-code warning. It must contain supported warning codes, never error codes; other attributes and targets fail with `E0209`. Recovery recognizes attributes as top-level boundaries. The syntax tree retains attribute text/trivia; the routine AST carries the validated suppression set through module rewriting and specialization. Statement, expression and routine spans include full consumed ranges for secondary diagnostics and reviewed fix-it edits. See README for the `paracine.diagnostics.v1` schema and warning controls.

## AST diagram

Run `paracine ast-diagram file.pcn` to print a labeled ASCII branch diagram, or add `-o diagram.txt` to write it to a file. The view shows the local parsed source before import resolution, constant resolution, type checking, or lowering. It can therefore display syntactically valid code that fails semantic analysis. Node labels show syntactic roles and normalized-source locations where available; pipelines are shown after parser desugaring. The existing `--ast` output is unchanged.

The diagram is followed by compact equations for a syntax dependency lattice. For every diagram node `#n`, `D(#n)` is the set containing that node and all its descendants. Lattice elements are all descendant-closed subsets of the diagram nodes, ordered by subset; bottom is the empty set, top is `D(#0)`, meet is intersection, and join is union. The displayed equations define each `D` using its immediate children, without enumerating the potentially exponential number of lattice elements. These are structural set equations, not equations between program values, an equivalence graph, or an optimization proof.

## Ownership and aliasing checks

The SAGE ownership pass tracks moves by record-field and fixed-array-element projection. Moving a non-copy field or constant-index element invalidates that place and its containing aggregates, but leaves disjoint sibling projections available; copy-typed projections do not move. Nested field and element reads/transfers are tracked recursively. Reinitializing a moved root-level record field or constant-index array element restores that projection without reviving other moved fields. Dynamic array indices are represented as an unknown element and conservatively conflict with every indexed element; dynamic writes do not establish reinitialization. Whole-aggregate reads and transfers are rejected while any contained projection remains moved. Branch joins union moves from reachable paths, and `while`, `each`/`for`, `from`, and `continue until` bodies are checked for newly moved projections that reach a possible back-edge; a terminal-only body is not considered a back-edge. `defer` expressions are checked in reverse registration order at normal and routine-exiting scope ends, so a value moved before cleanup is rejected.

Text views created from owned strings carry a backing-origin loan through local copies, record/array construction and stores, `ok`/`some` wrappers, `try`, and text-returning helper calls. Later use extends the loan; overlapping mutation, passage to a foreign routine without a no-escape contract, and returning a local-backed borrow are rejected. Borrow origins are conservatively unioned across aggregate fields and indices. Escaping closures are checked after capture discovery, including closures nested in or stored within returned aggregates and closures passed to calls (which are assumed to escape absent a no-escape signature); closure provenance follows local aliases by symbol identity, and move capture is the supported ownership transfer. Call-site alias conflicts are grouped by root binding, so distinct fields and array indices of the same root are conservatively considered overlapping. Exclusive borrows require a mutable root place.

These are deliberately conservative checks, not a formally complete lifetime calculus or a proof of soundness. General reference-typed values, variant/union payload provenance, arbitrary interprocedural lifetime relationships, raw/unsafe accesses, and precise break/continue CFG joins are not fully modeled. No machine-checked proof is provided; uncertain and unsupported cases must not be treated as proven safe.

## Generic specialization guards

Specialization follows the type checker's selected declaration and substitutions at every call site. AST call identity, rather than a line/column key or routine name alone, distinguishes imported calls and overloads. Only instances requested by non-generic routines and their transitive dependencies are generated; unused templates are filtered. A sorted, iterative work queue avoids recursive generation on the host stack. Emission and SKM instance lists are sorted by symbol. Concrete bodies are rechecked for types, ownership, and dependency capability constraints before lowering.

SKM structural facts categorize root and dependency uses, duplicate reuse, ordinary recursive reuse, cross-module uses, and cloned AST node counts. Ordinary and mutual recursion reuse the existing instance. Polymorphic recursion that revisits a template with different arguments is conservatively rejected with `E0345`. Dependency graphs are checked through strongly connected components, with each component weighted by its distinct instance count.

Hard limits (no silent truncation or fallback):

| Resource | Limit | Diagnostic |
|---|---:|---|
| Instances per compilation | 1024 | `E0346` |
| Instances per template | 128 | `E0346` |
| Dependency-path weight, including recursion components | 64 | `E0345` |
| Cloned expressions and statements per instance | 32768 | `E0346` |
| Cloned expressions and statements across instances | 262144 | `E0346` |
| Encoded identity input | 2048 bytes | `E0346` |

Code-size limits measure cloned AST nodes, not final native bytes or optimizer expansion. Missing call/declaration identities and incomplete substitutions report `E0344`; conflicting identities report `E0349`. Const routine generics (`E0343`) and foreign generics (`E0348`) fail explicitly. Closures inside generic instances receive fresh compilation-local identities and concrete checked parameter, result, capture and effect facts; they are no longer categorically rejected. These identities are deterministic within a compilation, not a stable cross-unit closure ABI.

Generated symbols use the reserved `_PCG1_` prefix followed by hexadecimal UTF-8 bytes of an unambiguous length-prefixed identity: module owner, routine name, generic and value arity, parameter modes and canonical positional types, return type, sorted constraints/effects, and concrete arguments in declaration order. Parameter spelling, call locations, absolute host paths, and hash-table order do not participate. File-backed graph ownership uses the module header or project/package-relative path, prefixed by package name and exact version when applicable. Imports are scoped with versioned `__pcn_module_v1_` linkage identities; repeated paths are loaded once and duplicate logical module identities are rejected. In-memory compilation without a source path retains its existing owner policy. This naming scheme is not a claim of cross-compiler ABI compatibility or generic COMDAT coalescing.

Source-only `link --lto` merges token-equivalent generic definitions across input units and rejects differing bodies/signatures with `E0349`. Whitespace/comments and end-of-file layout do not affect definition equality; internal layout does. All calls then share the same checked concrete instance. The bootstrap still requires globally unique routine names and permits a module header only in the first LTO source. It does not provide namespace-aware separate compilation, generic object manifests, or native COMDAT/ODR coalescing. Repeated specialization symbols across separately compiled `.pcn` link inputs are rejected with `E0530` and guidance to use source-only LTO; prebuilt-object conflicts remain the native linker's responsibility.

## Closure and text backend representations

Closure conversion consumes the type checker's authoritative signatures and SAGE capture facts, including concrete generic instances. Nested closures are recursively synthesized with lexical captures, including transitive captures needed to construct a child environment inside its parent. Named, aliased, grouped and indexed closure calls invoke the stored environment rather than reconstructing captures from current locals. The native Windows x64 environment stores owned captures inline and borrowed captures in pointer-backed fields; borrowed record mutation retains referent identity. Escaping closures may promote immutable scalar captures to environment-owned values. Mutable or reference-backed borrows are rejected. Move closures can own heap-backed strings and recursively owning records, tuples, and fixed arrays; closure-valued captures recursively propagate escape validation and environment ownership. Owned environments use explicit closure moves and recursive scope cleanup, while capture parameters remain caller-owned across repeated calls.

The PCIR interpreter and C++20 exporter retain the same checked capture field names, permitting shared extraction and cleanup instructions. Rich C++ export uses a standalone managed-value runtime for closures, strings, borrowed text, aggregates, options/results, floating values and existing I/O operations; scalar-only programs retain the compact exporter. Borrowed string views do not extend backing ownership, and use after backing destruction traps. This managed representation is a semantic export, not the native binary ABI, and uses allocations and reference counting. Foreign calls require explicit exporter bindings and otherwise fail; no binding-generation facility is supplied.

Run `python tools\test_cpp_export.py x64\Release\Paracine.exe` in an x64 MSVC developer shell for executable native/PCIR/C++ comparisons at `-O0` and `-O3`, plus runtime ownership and UTF-8 trap checks. Native Windows x64 move/drop lowering recursively handles owned strings in fixed arrays, tuples, ordinary records, and closure environments, including nested closure-valued captures, projected moves, replacement, and reverse-order cleanup. Recursive expansion is bounded to 4096 owned leaves; exceeding the bound fails with `E0426`. Owner-bearing tagged results/options, variants/unions, arbitrary reference-backed escapes, exclusive scalar-reference mutation and stable cross-unit closure ABI are not supported.

Parsing a construct does not imply full semantic or native-backend support. This describes the current bootstrap implementation, not complete edition-2026 parser conformance.
